Quillbot Provider

Quillbot provides free access to 2 chat models through a reverse-engineered API. It supports streaming, web search, and conversation history.

Quillbot models use the quillbot/ prefix.

from fishr import Client

client = Client()

response = client.chat.completions.create(
    model="quillbot/quillbot",
    messages=[{"role": "user", "content": "Hello!"}],
)
print(response.text)

Web Search

Use quillbot/quillbot-search for web search, or pass web_search=True with the standard model to enable it automatically.

from fishr import Client

client = Client()

# using the search model directly
response = client.chat.completions.create(
    model="quillbot/quillbot-search",
    messages=[{"role": "user", "content": "What happened in tech today?"}],
)

print(response.text)
from fishr import Client

client = Client()

# or enable web_search on the standard model
response = client.chat.completions.create(
    model="quillbot/quillbot",
    messages=[{"role": "user", "content": "What happened in tech today?"}],
    web_search=True,
)

print(response.text)

Conversation History

Quillbot supports conversation history. The full message history is formatted as a text prompt with System:, Assistant:, and User: prefixes.

from fishr import Client

client = Client()
conv = client.conversation(model="quillbot/quillbot")

conv.system("You are a helpful assistant.")
conv.ask("Remember: 42")
reply = conv.ask("What number did I say?")
print(reply)

conv.clear()  # reset history
ℹ History is formatted as text. Unlike other providers, Quillbot formats the entire conversation as a single text prompt rather than sending structured messages. Very long conversations may exceed context limits.

Limitations

  • Quillbot is a reverse-engineered API — it may break if the upstream service changes.
  • There is no uptime guarantee. Availability depends on the upstream service.
  • No image support — neither image input nor image generation is available.
  • Conversation history is formatted as plain text rather than structured messages, which may reduce quality on long conversations.
  • Rate limits may apply. Avoid rapid sequential requests.
  • Streaming uses SSE — some edge cases may produce partial output.
