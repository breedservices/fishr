NoTrack Provider

NoTrack provides free access to 3 chat models through a reverse-engineered API, including a reasoning model. It supports streaming and conversation history with chat ID tracking.

NoTrack models use the notrack/ prefix.

from fishr import Client

client = Client()

response = client.chat.completions.create(
    model="notrack/fast",
    messages=[{"role": "user", "content": "Hello!"}],
)
print(response.text)

Streaming

Set stream=True to receive chunks as they arrive.

from fishr import Client

client = Client()

response = client.chat.completions.create(
    model="notrack/standard",
    messages=[{"role": "user", "content": "Tell me a story"}],
    stream=True,
)

for chunk in response:
    print(chunk.choices[0].delta.content or "", end="")

Conversation History

NoTrack supports conversation history by maintaining a chat_id across requests. This allows the model to reference previous messages in the same chat session.

from fishr import Client

client = Client()
conv = client.conversation(model="notrack/standard")

reply1 = conv.ask("Remember: the secret number is 7")
print(reply1)

reply2 = conv.ask("What is the secret number?")
print(reply2)

conv.clear()  # reset history and start a new chat
ℹ Chat IDs are tracked automatically. The provider maintains a chat_id internally. Calling conv.clear() resets the chat ID, starting a fresh conversation on the server side.

Limitations

  • NoTrack is a reverse-engineered API — it may break if the upstream service changes.
  • There is no uptime guarantee. Availability depends on the upstream service.
  • No image support — neither image input nor image generation is available.
  • No web search — none of the NoTrack models support web search.
  • No system message support — system messages in the conversation are ignored.
  • Rate limits may apply. Avoid rapid sequential requests.
  • Streaming uses SSE — some edge cases may produce partial output.
